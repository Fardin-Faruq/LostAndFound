# Sprint 1 Plan - Lost2Found

## Sprint Goal
Build the foundational project structure, CI pipeline, authentication system, and core reporting functionality for lost and found items.

## Sprint Backlog

| ID | User Story | Status |
|---|---|---|
| **US-1.1** | As a student, I want to register for an account using my university email so that I can report and claim items. | ✅ Done |
| **US-1.2** | As a student, I want to log into my account securely so that I can manage my reports. | ✅ Done |
| **US-2.1** | As a student who lost an item, I want to submit a lost report with details (category, date, location, description) so that others can help find it. | ✅ Done |
| **US-2.2** | As a student who found an item, I want to submit a found report with details so that the owner can be located. | ✅ Done |
| **US-3.1** | As a student, I want to view a list of all active lost and found reports so that I can check if my item was found or if I found someone else's item. | ✅ Done |
| **US-7.2** | As a developer, I want a CI/CD pipeline to automatically lint and test code on every pull request so that code quality is maintained. | ✅ Done |

## Definition of Done (DoD)
- Code is pushed to version control.
- GitHub Actions CI pipeline passes (linting and tests).
- Backend APIs for Auth, Lost, Found, and Item Listings are functional and tested.
- Frontend forms validate data and submit to APIs successfully.
- Code follows project directory structure and style guidelines.
- Agile documentation is updated.
